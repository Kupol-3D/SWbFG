# sa_fdm_lab — атмосферный стенд TASK3

Один профиль **JSBSim**, собственная открытая greybox-геометрия, кабина и
внешняя камера. Поддержку веса даёт явно вымышленный repulsor. Это инженерный
эксперимент массой 1000 кг, а не физические данные какого-либо корабля.
Решение, измерения и ограничения: [FDM_SPIKE](../../docs/FDM_SPIKE.md).

Запускать из корня репозитория с установленными FG/SimGear/FGData **2024.1.7**:

```sh
python3 tools/test_sa_fdm_lab.py
python3 tools/run_sa_fdm_lab.py \
  --fgfs /path/to/fgfs \
  --fg-root /path/to/fgdata \
  --fg-scenery /path/to/Scenery/TerraSync \
  --output /tmp/sa-fdm-example
```

В macOS `--fgfs` может указывать на `FlightGear.app/Contents/MacOS/FlightGear`.
Каталог `--output` должен быть новым и вне репозитория. Launcher создаёт
отдельный `FG_HOME`, отключает TerraSync и реальную погоду, не меняет
пользовательские настройки и не открывает сетевой property server.
Scenery используется только для чтения. Нужен её локальный район 37.6° N,
122.3° W и shared Models. Без scenery результат визуальной приёмки неполон.
Низкая начальная высота и старт на земле не поддерживаются.

Автоматический сценарий выполняется в реальном FlightGear. Nasal выдаёт
команды и печатает выборки с интервалом около 1 с; JSBSim интегрирует движение
с штатным шагом FG. После 205 с симуляционного времени FG завершает работу.
`telemetry.csv`, `summary.json`, `version.txt`, `flightgear.log` остаются в
каталоге результата. Ненулевой exit code launcher означает незавершённый
прогон или нарушение границ. `--headless` проверяет FDM, но не внешний вид.

На старте скрипт **однократно** записывает `ic/*` из стартовых координат и
вызывает `simulation/reset=1`: в FG 2024.1.7 путь `trim=0` иначе теряет
начальные координаты. Это происходит до отсчёта эксперимента; во время
прогона скрипт не пишет позицию, скорости или ориентацию. Самолётный trim
для этой схемы отключён; причина и неуспешная попытка сохранены в отчёте.
Переинициализация через меню Reset пока не поддерживается: перезапустить FG.

Для ручного сценария добавить `--manual --timeout 900`. Автопилот маршрута
и автоматическое завершение выключены; поддержка веса и стабилизация FDM
работают. Открытая кабина имеет свободный взгляд вперёд, `v` меняет камеру.
Управление рассчитано на латинскую раскладку:

| Клавиши / свойство | Действие |
|---|---|
| W / S | `lab/throttle` ±0.1, пределы 0..1 |
| B | `lab/brake` 0/1, активное торможение вдоль корпуса |
| J / L, K | `lab/yaw` −1/+1, затем 0; предел скорости рыскания ±10°/с |
| R / F | `lab/altitude-ft` ±50 ft; клавиатурный диапазон 2500..4000 ft |
| Штатные aileron / elevator | Команда крена ±14.3°, тангажа ±9.7° |

Все `lab/*` находятся под `/fdm/jsbsim/`. Обычный газ двигателя и педали
не управляют этим стендом: двигателей JSBSim нет, силы задаются напрямую.
Точные малые значения задаются в File → Browse Internal Properties.
Границы подтверждённого режима уже диапазонов клавиатуры: см. отчёт.

Ручной сценарий (секунды от завершения инициализации):

1. 0–30: нулевая тяга, B включён. Записать h MSL/AGL, скорость, крен,
   тангаж и вертикальную скорость в начале/конце; проверить отсутствие дрейфа.
   На 10–15 с дать `aileron=0.4`, `elevator=-0.3`, затем отпустить. Проверить
   возврат к горизонту. Автоматический сценарий включает этот импульс.
2. 30–50: B выключить, `throttle=0.02`. Записать малую скорость и h.
3. 50–75: `throttle=0.12`. Записать скорость каждые 5 с, высоту и отклонения.
4. 75–90: тяга 0, B включить. Записать время снижения скорости ниже 1 м/с.
5. 90–115: L, по мере приближения к курсу 180° нажать K. Поддержать зависание;
   записать достигнутый курс, крен/тангаж и изменение высоты.
6. 115–180: развернуть нос к стартовой точке, дать тягу до 0.2; ограничить
   скорость 25 м/с. По приближении уменьшить тягу и включить B. Для точного
   сравнения автоматический сценарий корректирует курс и скорость по
   координатам старта; ручной пилот может использовать карту/свои замеры.
7. Около 155 с: R (+50 ft), через 15 с F (возврат к 1000 м MSL).
   Записать высоту, максимальную вертикальную скорость и время установления.
8. До 205 с: тяга 0, B включён, K. Записать остаточную скорость, дистанцию
   до старта, h и отклонения. Отметить solver/trim/Nasal errors, NaN и падение.

Форма записи: `time_s,phase,altitude_m,airspeed_mps,roll_deg,pitch_deg,`
`heading_deg,north_m,east_m,distance_m,throttle,brake,yaw,support_lbf,`
`down_mps,agl_m`. Ручной сценарий предоставлен для воспроизведения; его
пилотирование человеком не заявляется как уже выполненное.

Геометрия: метры, начало в CG/VRP, оси FG-модели +X назад, +Y вправо,
+Z вверх; нос −X. Экспорт AC3D `(x,z,-y)`, загрузчик SimGear восстанавливает
`(x,-z,y)`. JSBSim structural имеет те же направления, но координаты XML
явно задаются с `unit="M"`; BODY — нос/право/вниз. Камерные offsets —
право/верх/назад, камера `(−0.5,0,0.8)` в координатах модели.
Опоры `(−2,0,−0.5)`, `(1.5,±1.5,−0.5)`; центры сопел
`engine-1/2=(1.5,∓1.6,−0.05)`; `muzzle-1/2=(−2.4,∓0.7,0.1)`.
Узлы `hull`, `cockpit`, `engine-1/2`, `muzzle-1/2`; 96 треугольников,
без текстур. Сопла и дула — интеграционные маркеры без боевой логики.
