# sa_tie — TIE/ln greybox

`ship_id=tie`, `team_id=empire`. Первый интеграционный ассет TASK2:
сферическая кабина, две шестигранные панели, интерьер, два двигателя,
два дула. Это профиль просмотра с `<flight-model>null</flight-model>`.
Пакет не содержит аэродинамику, сетевой адаптер или боевые системы.

## Происхождение и размеры

Автор собственной геометрии, экспортера и XML: Space Arena contributors,
при содействии OpenAI Codex, 2026. Исходник — `Sources/build_tie.py`;
геометрия описана непосредственно в Python, без Blender/bpy. Экспорт
не переписывает исходник. Внешние модели, изображения, текстуры и ресурсы
игр не использованы. Исходник, экспорт и интеграционные файлы распространяются
под **GPL-2.0-or-later**; полный текст GPL v2 включён в `LICENSE`.
Разрешены изменение и распространение на условиях этой лицензии.
Название и образ TIE относятся к Star Wars / Lucasfilm; лицензия собственных
файлов не предоставляет прав на товарные знаки и исходное произведение.

Зафиксированный вариант — имперский одноместный TIE/ln с прямыми панелями.
Размеры greybox: **7.2 м вдоль X × 6.7 м вдоль Y × 8.8 м вдоль Z**,
по проектному ориентиру из [`docs/SHIP_SURVEY.md`](../../docs/SHIP_SURVEY.md).
Это выбранный масштаб проекта, не заявление о точных канонических размерах.
[Официальная карточка TIE](https://www.starwars.com/databank/tie-fighter)
использована для идентификации варианта: она указывает другую длину 8.99 м.
Изображения с карточки в пакет не включены. Диаметр сферы 3.10 м,
внутренний радиус 1.43 м; пропорции интерьера — авторские допущения.
Масса, инерция и параметры FDM из этих размеров не выводились.

`Sources/SHA256SUMS` фиксирует SHA256 оригинального Python-исходника и
экспорта `Models/tie.ac`. Для изменения формы редактируют исходник,
затем осознанно обновляют экспорт и хеши:

```sh
python3 Aircraft/sa_tie/Sources/build_tie.py
python3 Aircraft/sa_tie/Sources/build_tie.py --check
python3 -m unittest discover -s tools -p 'test_sa_tie.py' -v
```

Экспорт детерминирован, использует только стандартную библиотеку Python.
Все поверхности уже триангулированы. **5 936 треугольников**, включая интерьер,
рамки и рёбра панелей, против лимита 25 000. Текстур нет (0 байт, лимит 2K
не используется). Отдельные узлы для будущего адаптера сохранены.

## Оси и точки

Все размеры ниже в метрах. Ноль — центр сферы кабины. Модельные оси FG:
**X назад, Y вправо по пилоту, Z вверх**, нос смотрит по `(-1,0,0)`.
Это не aircraft-body FDM `(X вперёд, Y вправо, Z вниз)`:
`body = (-model.x, model.y, -model.z)`.

Генератор работает в модельных осях FG, но записывает AC3D как
`ac = (model.x, model.z, -model.y)`. Штатный SimGear AC loader преобразует
`model = (ac.x, -ac.z, ac.y)`. XML-обёртка не добавляет второй поворот.
Смещения **камер** имеют другую семантику — `(right, up, aft)`:
`view = (model.y, model.z, model.x)`. Это подтверждается реализациями
[ACProcessPolicy](https://github.com/FlightGear/simgear/blob/release/2024.1/simgear/scene/model/ModelRegistry.cxx)
и [View](https://github.com/FlightGear/flightgear/blob/release/2024.1/src/Viewer/view.cxx).

| Точка / узел | Модельные X, Y, Z | Направление / назначение |
|---|---|---|
| Глаза, камера пилота 0 | `-0.25, 0, 0.35` | вперёд `-X`, FOV 80° |
| Камера переключателя 3 | `-0.25, 0, 0.35` | вправо 53°, вниз 51°, FOV 60° |
| Внешняя камера 1 | `-18, 13, 8` | к центру, FOV 45°, heading-offset 180° |
| Камера двигателей 2 | `18, 9, 5` | к центру, FOV 45°, heading-offset 180° |
| Сиденье, центр подушки | `0.285, 0, -0.67` | спинка позади глаз |
| `engine-1` | `1.63, -0.62, 0.12` | выход по `+X` |
| `engine-2` | `1.63, 0.62, 0.12` | выход по `+X` |
| Линзы свечения | `1.636, ±0.62, 0.12` | реальные поверхности, выход по `+X` |
| `muzzle-1` | `-1.725, -0.52, -0.82` | по `-X` |
| `muzzle-2` | `-1.725, 0.52, -0.82` | по `-X` |
| `panel-light-switch` | `-0.61, 0.48, -0.40` | ось качания `+Y` |
| Низ панелей, четыре нижних угла | `±1.8, ±3.238, -4.4` | ориентиры размещения, без контактов FDM |
| Верхний люк | `0, 0, 1.58` | ориентир выхода; эвакуация не реализована |

Точки `engine-*` и `muzzle-*` имеют собственные `loc` в AC3D;
геометрия дул и линз лежит в локальных плоскостях этих узлов. `hull`
содержит внешний корпус, панели, стойки и двигатели; `cockpit` — интерьер.
Фронтальная часть обеих сферических оболочек открыта. Окно имеет рамку,
центральное кольцо и восемь лучей; стекло опущено, чтобы избежать сортировки
прозрачных поверхностей. Кабина не скрывает наружную модель при виде изнутри.
Статический тест проверяет зазор камеры до реальных треугольников >0.35 м,
девять свободных лучей вперёд и прямую видимость переключателя.
Near plane из кабины 0.05 м. Свободное перемещение головы не ограничено:
большие смещения могут вывести камеру за оболочку.

## Просмотр в FlightGear

Нужны отдельно установленные FlightGear и FGData, целевая версия 2024.1.4.
Пакет не копируется в FGData. Из корня репозитория, подставив свои пути:

```sh
FG_HOME="/tmp/sa-tie-viewer" /path/to/fgfs \
  --no-default-config --disable-launcher \
  --fg-root="/path/to/fgdata" \
  --fg-aircraft="$PWD/Aircraft" --aircraft=sa_tie --fdm=null \
  --fg-scenery="/path/to/Scenery/TerraSync" \
  --lat=37.6 --lon=-122.36 --altitude=3000 --heading=180 --in-air \
  --timeofday=noon --disable-terrasync --disable-real-weather-fetch \
  --disable-ai-models --disable-sound --disable-hud --geometry=1280x800
```

На macOS вместо `/path/to/fgfs` используется бинарник
`FlightGear.app/Contents/MacOS/FlightGear`. `FG_HOME` — отдельная временная
директория, чтобы не менять личный профиль; это переменная окружения,
а не аргумент `--fg-home`. В Windows задают `FG_HOME` средствами оболочки
и передают абсолютный путь к папке `Aircraft` вместо `$PWD/Aircraft`.
Поддержка ОС не считается проверенной по одной XML-проверке.

Клавиша **v** переключает виды: 0 пилот → 1 спереди/справа → 2 двигатели →
3 переключатель. Далее идут штатные виды FG; возвращение к 0 — через
меню видов или `/sim/current-view/view-number=0`.
В виде 3 левой кнопкой нажать светлую качалку справа на консоли. Один клик
меняет `/sim/space-arena/visual/tie-panel-light` (`bool`, изначально `false`),
поворачивает качалку и включает зелёные полоски/индикатор. Повторный клик
выключает их. Это эмиссия материала, без динамического освещения стен.

В **File → Browse Internal Properties** открыть
`/sim/space-arena/visual/throttle`, задать `0`, `0.5`, `1` и смотреть вид 2:
обе красные линзы меняют эмиссию. Начальное значение `0`.
Значения в пределах `0..1` — вход визуального контракта, не тяга FDM;
обычный throttle джойстика ещё не подключён. Foils для TIE отсутствуют.
XML использует штатные `material`, `pick`, `rotate` анимации, без Nasal;
см. [описание анимаций FG](https://wiki.flightgear.org/Howto:Animate_models).

## Проверка и ограничения

Статические тесты проверяют XML и все пути, обязательные узлы, границы
геометрии, бюджет, нормали сфер, поверхность/доступность переключателя,
контракт свойств, локальный эффект освещения и воспроизводимость экспорта с SHA256.
Они не доказывают визуальную приёмку, FPS, устойчивость FDM или работу MP.

### Исправление освещения — 9 ноября 2026

На FG/SimGear/FGData 2024.1.7, OSG 3.6.5, macOS/M2 Pro воспроизведён
пересвет: на BIKF в ясную погоду ALS-путь `Effects/model-default` выводил
модель почти исключительно чёрным и белым. Та же геометрия и материалы
в обычном шейдере сохраняли серые оттенки. Отсутствующих текстур у пакета нет;
добавление явной белой текстуры в диагностической копии проблему не устранило.

`Effects/greybox.eff` назначает модели штатный материал `Effects/model-combined`
с собственным ALS-путём. С ним на той же сцене сохраняются серые оттенки,
затенение и цветная эмиссия. Эффект полностью наследует выбор техник
FlightGear, без отключения ALS и изменения глобальных настроек освещения.
Проверено со штатным качеством шейдеров моделей `shaders/model=3`.

В `Models/tie.xml` эффект указан как default, а также явно назначен четырём
анимированным поверхностям. Это нужно, чтобы автоматически создаваемые
SimGear эффекты material-animation не заменяли материал свечения на
`Effects/material-diffuse`, наследующий проблемный `model-default`.
Свойства throttle и переключателя, геометрия и её SHA256 не менялись.

Для воспроизведения используется команда просмотра выше, где координаты
`--lat=... --lon=...` заменены на `--airport=BIKF`, высота — `--altitude=1000`,
и добавлены:

```sh
--metar="XXXX 012345Z 00000KT 19SM SKC 15/M99 Q1013 NOSIG" \
--prop:/sim/rendering/shaders/skydome=true \
--prop:/sim/rendering/shaders/use-shaders=false
```

После исправления проверены серые оттенки в камере 1, вид из кабины,
красная эмиссия обоих двигателей и зелёная эмиссия подсветки в режиме ALS.
Проверены оба значения `use-shaders` при включённом `skydome`.
Свечение в этой повторной проверке задавалось через визуальные свойства;
проверка мышью от 7 ноября приведена выше. Новая проверка эффекта добавлена
в `tools/test_sa_tie.py`; актуальный набор пакета содержит 10 тестов.
Общий набор проекта после исправления: **86 тестов пройдены**.
