# TASK3 — отчёт о выполнении: тяговый атмосферный полёт

**Статус: экспериментальный стенд реализован, статические проверки и реальный
прогон FlightGear длительностью более трёх минут выполнены.** Исходные
требования: [TASK3](../TASK/TASK3.md). Дата отчёта: **11 ноября 2026**.
Испытания проведены **10 ноября 2026**. Окончательный go/no-go принимает
ведущий; положительный результат относится к режиму с игровыми помощниками.

## Что требовалось

Экспериментально определить, можно ли без изменения движка FlightGear получить
устойчивый атмосферный полёт аппарата на тяге с поддержкой веса и управлением
на малой скорости. Подготовить один автономный стенд с собственной простой
геометрией и камерой, выбрать один backend после сравнения YASim/JSBSim,
описать допущения и пределы режима, добавить тест ресурсов и ручной сценарий.

Критерий runtime-проверки — минимум три минуты реального FG без solver-failure,
NaN и самопадения в заявленном режиме, с измерениями скорости, высоты и
отклонений. Статические тесты и скриншоты сами по себе этот критерий не заменяют.

## Что сделано

- Создан автономный пакет [Aircraft/sa_fdm_lab](../Aircraft/sa_fdm_lab/README.md):
  собственная greybox-геометрия AC3D, открытая кабина, внешний вид и две камеры.
  Геометрия содержит 96 треугольников, без текстур и сторонних игровых ресурсов.
  Исходный генератор, SHA256, оси, точки опор и происхождение документированы;
  лицензия — GPL-2.0-or-later.
- После короткого сравнения выбран **JSBSim**. Реализован один профиль
  [sa_fdm_lab.xml](../Aircraft/sa_fdm_lab/sa_fdm_lab.xml); второй законченный
  профиль YASim не создавался.
- Заданы инженерные допущения: масса 1000 kg, тензор инерции, тяга до 8000 N,
  сопротивление, активное торможение, поддержка веса и стабилизирующие моменты.
  Поддержка веса — явно вымышленный repulsor в локальной вертикали; боковое
  демпфирование и удержание ориентации также обеспечиваются помощником.
  Массы и тяги не выдаются за канонические характеристики корабля.
- Добавлен [tools/test_sa_fdm_lab.py](../tools/test_sa_fdm_lab.py): проверка
  конфигурации, локальных ресурсов, геометрии, камер, ограничителей, происхождения
  и соответствия SHA256 файлов записанному эксперименту.
- Добавлен [tools/run_sa_fdm_lab.py](../tools/run_sa_fdm_lab.py): запуск
  настоящего FG с отдельным временным `FG_HOME`, сбор телеметрии и проверка
  завершения маршрута. Nasal выдаёт команды; движение интегрирует JSBSim.
- В [README пакета](../Aircraft/sa_fdm_lab/README.md) записаны команда запуска,
  управление и отдельный ручной сценарий. Автоматический маршрут включает
  зависание, импульс крена/тангажа и восстановление, малую скорость, разгон,
  торможение, разворот, возврат к старту и перестановку высоты.
- Подготовлен [docs/FDM_SPIKE.md](../docs/FDM_SPIKE.md): сравнение backend,
  механика и вымышленные силы, единицы, параметры, границы и результаты.
  Ядро FG, сторонние модели и личные настройки для стенда не изменялись.

## Реальный прогон и измерения

Окружение: macOS 26.5.1 (25F80), arm64; FlightGear, SimGear и FGData
**2024.1.7**, FG revision `7241807173248abd838e2ab11337fbc5b2ae20b0`.
Нативная частота FDM — 120 Hz, ограничение кадров — 30 Hz. Спокойная атмосфера,
старт в воздухе на 1000 m MSL, район 37.6° N / 122.3° W.

| Показатель | Фактический результат |
|---|---|
| Длительность | 205.15 s симуляционного времени, 223.23 s wall time |
| Телеметрия и завершение | 201 выборка, exit code 0, итоговая проверка PASS |
| Зависание | h 1000.00146..1000.00733 m, скорость не более 0.00319 m/s |
| Управление на зависании | пик крена 5.8101°, тангажа 2.9622°; после отпускания возврат к горизонту |
| Малоскоростной режим | скорость до 2.7719 m/s |
| Разгон | 22.2266 m/s в момент включения тормоза |
| Торможение | скорость ниже 1 m/s примерно за 3 s |
| Поворот | разворот к курсу 180° на нулевой по FG airspeed скорости |
| Максимальная скорость маршрута | 22.9738 m/s на возврате |
| Команда набора +50 ft | достигнуто 1015.24697 m, затем восстановлена исходная высота |
| Финальная высота | 1000.007335 m, ошибка около +0.007335 m |
| Финальная скорость | 0 по FG airspeed; вертикальная около −1.15e−8 m/s вниз |
| Ошибка возврата к старту | 3.31292 m; конечный курс 179.88283° |

В принятом прогоне не зафиксированы solver/trim/Nasal failure, NaN или
самопадение. Миллиметровая ошибка высоты описывает идеализированный регулятор,
а не точность реального аппарата. Маршрут выполнен автоматически в настоящем
FG; прохождение всего сценария человеком не заявляется.

Отдельно проведены нативные опыты JSBSim:

- **Зависание 205 s:** exit code 0, 411 конечных числовых выборок;
  высота 1000.00526..1000.01262 m.
- **Отключение поддержки веса на 2-й секунде:** на 5-й секунде высота
  956.05296 m, скорость снижения 29.34698 m/s. Потеря около 44 m за 3 s
  подтверждает необходимость поддержки веса и отсутствие заморозки высоты.

## Неудачные попытки и решение инициализации

Обычный самолётный trim на нулевой скорости не сошёлся: его переменные
alpha/elevator/throttle не соответствуют схеме с независимой поддержкой веса.
Реальный отрицательный вывод сохранён в
[trim-attempt.txt](../docs/fdm_lab_evidence/trim-attempt.txt); он не считается
успешным solve. Итоговый профиль не требует офлайн-подбора коэффициентов YASim.

При `trim=0` в FG 2024.1.7 обнаружена потеря стартовой позиции после `RunIC()`.
Пакет обходит её без правки движка: один раз после `fdm-initialized`, до
измерений, задаёт штатные `ic/*` из presets и вызывает `simulation/reset=1`.
Во время измеряемого полёта сценарий не пишет позицию, скорость и ориентацию.

В сохранённом выводе также есть предупреждения об отсутствии звукового файла,
обращении к throttle[0] при отсутствии штатных двигателей и невозможности
сохранить начальный снимок FDM (`Failed to save initial FDM property state`).
Они описаны в FDM_SPIKE. Повторный Reset из меню не поддерживается: стенд
следует перезапускать отдельным процессом.

## Проверки и воспроизведение

На момент реализации TASK3 выполнены **9 тестов стенда** и **98/98 тестов
проекта** на Python 3.11.6 с закреплёнными зависимостями в отдельном временном
venv. Для loopback TLS-тестов потребовалось разрешить локальные сокеты вне
песочницы. Это исторические числа до последующей интеграции других задач,
а не число тестов текущего объединённого репозитория. Python 3.14 отдельно
в этом эксперименте не проверялся.

Для повторения статической проверки из корня проекта:

```sh
python3 Aircraft/sa_fdm_lab/Sources/build_lab.py --check
python3 tools/test_sa_fdm_lab.py
```

Для реального FG-прогона:

```sh
python3 tools/run_sa_fdm_lab.py \
  --fgfs /path/to/fgfs \
  --fg-root /path/to/fgdata \
  --fg-scenery /path/to/Scenery/TerraSync \
  --output /tmp/sa-fdm-task3-repeat
```

Каталог результата должен быть новым и вне репозитория. Для ручного
пилотирования добавить `--manual --timeout 900`; последовательность действий
и форма записи измерений приведены в README пакета. При составлении этого
отчёта 11 ноября новый полёт не выполнялся: результаты взяты из сохранённых
артефактов испытаний 10 ноября.

## Итог и ограничения

**Технический GO для продолжения атмосферного прототипа с явно вымышленными
помощниками.** Без изменения движка достигнут управляемый полёт, включая
зависание и возврат. Одна продольная тяга вес аппарата не поддерживает.
Окончательный go/no-go интеграции остаётся решением ведущего.

Подтверждён только испытанный режим: спокойная атмосфера, старт в воздухе
на 1000 m MSL в указанной точке, скорость до 25 m/s, малые углы, включённые
поддержка веса/стабилизация и небольшие перестановки высоты. Не проверены
сильный ветер, турбулентность, большие углы, отказ стабилизации, взлёт/посадка
на опоры, произвольная масса, расход энергии, мультиплеер и бой, другие ОС.
Вакуум, орбиты, точный канон и обычная аэродинамическая реализуемость не
заявляются. Статические тесты проверяют ресурсы и конфигурацию, но не
доказывают аэродинамическую устойчивость.
