# Space Arena с разрушителем и внутренним ангаром

Готовое размещение **в составе репозитория**. Сам корабль и все его LOD лежат
в `Aircraft/sa_venator`, здесь только XML-ссылка и объекты арены. Пересборка,
Blender, `star_destroyer_pack` и локальный `work/runtime` для загрузки не нужны.

Это вариант той же арены, что `../space_arena`: Rebels сохранены, имперские
greybox-заглушки заменены цельной моделью Venator с внутренним боковым ангаром.
Исходная greybox-арена оставлена отдельно для разработки и её старых тестов.
Одновременно подключать обе арены не нужно: иначе Rebels продублируются.

## Просмотр после клонирования

При установленном FlightGear **с FGData и штатным UFO**, из корня репозитория:

```sh
fgfs --launcher=0 --no-default-config=1 \
  --fg-aircraft="$PWD/Aircraft" \
  --fg-scenery="$PWD/scenery/space_arena_carrier" \
  --aircraft=ufo --in-air \
  --lon=-122.46517 --lat=37.42578 --altitude=1800 \
  --heading=143.13 --pitch=0 --roll=0 --vc=0 \
  --timeofday=noon --enable-terrasync
```

`fgfs` должен быть в PATH; иначе укажите путь к установленному бинарнику.
Высота `1800` здесь в **футах MSL**, не AGL. UFO — штатный инструмент осмотра,
не игровой TIE. TerraSync получает обычную земную scenery средствами FG;
сами модели этой арены уже находятся в репозитории.

## Состав и состояние

- Здесь — размещение, XML-ссылка и собственные модели Rebels. Три `.ac` LOD,
  модельная XML-обёртка и layout хранятся только в `Aircraft/sa_venator`.
- Проектный размер корпуса 3000 м; это игровой масштаб, не каноническая длина.
- Корпус и ангар — единая модель каждого LOD; отдельного дублирующего ангара нет.
- Боковой проём вместо наружного короба, исходное днище сохранено.
- Размещение в этой сцене пока статическое preview (`OBJECT_STATIC_AGL`),
  а не утверждение, что корабль принципиально неподвижен. AI/FDM-движение
  должно использовать тот же Aircraft-пакет без копирования его геометрии.
- Подвешенные декоративные TIE удалены, створки ворот статически открыты.
- Пять локальных стартовых позиций проверены геометрически; физический спавн,
  поддержка палубой, столкновения и сетевой матч **не подключены**.
- Модель и ангар наблюдались в реальном FG 2024.1.4, включая новую ссылку
  сцены на Aircraft-пакет через `FG_AIRCRAFT`. Цель проекта — 2024.1.7;
  runtime-переключение LOD и производительность на целевом GPU не приняты.

Итого LOD корабля: **371341 / 79857 / 47825** треугольников. Хэши файлов
размещения перечислены в `manifest.json`; зависимость от Aircraft-пакета
закреплена отдельным хэшем его `Sources/BUILD_MANIFEST.json`. Сам manifest
в свой список хэшей не входит.

## Исходники и лицензии

См. [LICENSE_ATTRIBUTION.md](LICENSE_ATTRIBUTION.md). Код генераторов и собственная
greybox-геометрия не меняют лицензию сторонних мешей разрушителя/ангара.
Исходная арена сохранена побайтно в `source/manifest.json` и `source/`.
Не запускайте исторический `source/src/generate_package.py` поверх этой сцены.

Сборщик `tools/build_carrier_arena.py` — отдельный инструмент разработки
автономного локального overlay, а не зависимость запуска этой поставки.
Внешнему экспериментальному сборщику можно передать `Aircraft/sa_venator/Models`
и старую `scenery/space_arena`; его выход с копиями моделей должен находиться
вне репозитория. В поставке этого репозитория канонические меши только в Aircraft.
