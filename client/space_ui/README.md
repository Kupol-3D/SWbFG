# Первый экран Space Arena — TASK6

Внешний GUI на **Tkinter/ttk** без дополнительных Python GUI-библиотек.
Выбор фракции/корабля — **DEMO**, реальный доступный запуск — только штатный
**c172p SOLO**. Это разные действия: выбранный X-wing не подменяется c172p.

## Запуск

Из корня репозитория, используя подготовленный Python проекта:

```sh
python -m client.space_ui
```

Или явно загрузить общий пример (без секретов):

```sh
python -m client.space_ui --profile client/space_ui/profile.example.json
```

`--help` работает без графической среды. Никакие профили не ищутся в домашней
папке, не сохраняются автоматически и не исполняются при загрузке.
Открытие окна не запускает FG и не устанавливает соединение.

### Tkinter

Tk должен быть доступен **тому же Python**, которым запускается клиент:

```sh
python -m tkinter
```

Это отдельная проверка настоящего окна Tcl/Tk, не FlightGear.
В Ubuntu для системного Python обычно нужен пакет `python3-tk`:

```sh
sudo apt install python3-tk
```

Если используется отдельный Python 3.14, системный пакет может относиться
к другой версии: требуется Tk для выбранной сборки Python. `pip install
tkinter` не заменяет стандартный модуль с его нативной библиотекой.
В установщиках Python для Windows/macOS проверить наличие Tcl/Tk.
Нужна настоящая desktop-сессия; отсутствие Tk/display даёт понятную ошибку
и код выхода 2, а не выдуманное успешное headless-окно.

## Что делает экран

1. **Профиль:** путь к `fgfs`/`fgfs.exe` (или имя из PATH), callsign,
   необязательный будущий endpoint. Путь с пробелами допустим.
2. **Команда и каталог:** Rebels/Empire, первый истребитель доступен только
   для демонстрационной проверки выбора; остальные строки заблокированы
   с причиной. Это не скачанные модели, реальные жизни или серверный допуск.
3. **Проверить выбор (DEMO):** mock-ответ, без spawn, сети и расходования слота.
4. **Сеть:** relay ещё unavailable. Нет настоящего handshake, авторизации,
   сервера, надписи «подключено» или обещания шифрования игрового потока.
5. **Вылет: c172p SOLO:** реальный запуск установленного FG через список
   аргументов, без shell. Данные демо-команды/корабля/endpoint в FG не идут.

Клиент не загружает наш add-on и не выбирает новый starship-пакет. Он явно
отключает запомненные MP-настройки и не включает TerraSync: c172p и scenery
для KSFO/28R нужно подготовить заранее в своей установке FG.
Целевая версия из `docs/SOURCES.json` — требование команды, **не результат
автоматической проверки установленного fgfs**. Сверить её через `fgfs --version`.

После старта UI не ждёт завершения FG и остаётся отзывчивым; повторный запуск
одного собственного процесса блокируется до его выхода. PID/работающий
процесс не доказывают загрузку сцены или готовность к полёту.
stdout/stderr FG наследуются терминалом — запускать GUI из терминала для
диагностики ошибок FG. Клиент не создаёт общие runtime-логи в Git.

Закрывая окно при работающем FG, можно оставить FG работать самостоятельно.
Клиент не ищет и не останавливает другие процессы FG. Защита повторного
запуска действует внутри одного экземпляра клиента, не глобально на компьютере.

## Профили и безопасность

Кнопки «Загрузить»/«Сохранить как» используют только явно выбранный файл.
Рекомендуемое имя — `space-ui.local.json` (исключено `.gitignore`, правило
`*.local.json`); личный профиль лучше держать вне репозитория. Публичный шаблон —
`profile.example.json`. Старый `client/client.example.json` относится к
диагностическому CLI, имеет другой формат и не меняется этой задачей.

Поля GUI-профиля: `schema_version`, `fgfs`, `callsign`, `endpoint`, `team_id`,
`ship_id`. Неизвестные поля отвергаются, размер ограничен 64 KiB.
Endpoint пустой либо `wss://ASCII-host[:port]/mp`; логин/пароль, query,
fragment и control-символы не допускаются. DNS/сеть при проверке не вызываются.
Токенов в интерфейсе/формате нет; нельзя помещать их в endpoint или argv.
Загрузка профиля не запускает указанный исполняемый файл: перед нажатием
кнопки вылета проверяйте путь, особенно для полученного от другого человека файла.

## Проверки и границы

```sh
python -m unittest discover -s tools -p 'test_space_ui.py' -v
```

Тесты проверяют валидацию, mock-flow, argv и process lifecycle с подставным
дочерним процессом. Это **не** рендер Tk и **не** реальный полёт.
На машине с настоящим Tk/display можно отдельно проверить создание формы:

```sh
python -m client.space_ui.smoke
```

Команда создаёт окно, выполняет расчёт геометрии и закрывает его без запуска
FG. Выход 0 подтверждает только сборку формы; выход 2 / `NOT TESTED` означает,
что Tk/display недоступен, а не успешную проверку. Клики и визуальное качество
оцениваются вручную.
Инструкция визуальной/полетной приёмки: [MANUAL_TEST.md](MANUAL_TEST.md).

| Уровень | Статус поставки |
|---|---|
| Python/core/entrypoint, Linux headless | Автоматические проверки |
| Настоящее окно и клики, Linux desktop | Требуется ручной прогон |
| Настоящий FG/c172p из GUI | Требуется ручной прогон |
| Windows GUI/FG | Не проверено |
| macOS GUI/FG | Не проверено |
| Relay, VPS, матч | Не реализованы этим модулем |

TASK6 нельзя считать полностью принятой до успешного GUI/FG-прогона хотя бы
на основной целевой ОС. Installer, EXE, обновления, in-game Nasal, реальные
корабли, транспорт и матчевый авторитет в этот инкремент не входят.
