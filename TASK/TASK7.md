# TASK7 — Проверяемое ядро правил матча и бюджета кораблей

**Срок:** 2–3 рабочих дня. Ветка `feat/task7-match-core`.
Вход: `docs/TEAM_INTERFACES.md`, `docs/TEAM_PLAN.md`,
`docs/SPACE_ARENA_PLAN.md`. Это правила игры, не новый сервер урона.

## Цель
Отделить правила от FGMS/клиентского доверия. Подготовить детерминированное
offline-ядро, которое позже запустит выбранный ведущим авторитетный компонент.
Python допустим как тестовая реализация библиотеки, но без сетевого listener.

## Выход
- `match_core/` и `tools/test_match_core.py`: состояние + события → новое
  состояние/результат, без FG, wall-clock, random и внешних служб.
- `match_core/CONTRACT.md`: минимальные версии событий/snapshot и примеры
  JSON для UI/интегратора. `player_id` стабилен, callsign не ключ жизни;
  идентификаторы match/spawn/event предотвращают повторное применение.
- Join/team-lock, запрос появления из каталога своей команды (один активный
  корабль), один расход слота на конкретный тип при появлении; потеря аппарата
  закрывает его слот. Повторный запрос/reconnect не возвращает корабль.
- Подтверждённое уничтожение врага = +1, первое достижение 15 завершает матч;
  повторы, старый spawn/match, friendly fire и события после конца отвергаются.
  Авария расходует аппарат без kill-point. Источник «подтверждения» здесь
  доверенный тестовый вход, не проверка клиентского hit-claim.
- Исчерпание состава и таймлимит — явные настраиваемые fallback из плана,
  отделённые reason-code от победы по 15. Время передаётся событием.

## Готово, когда
Тесты покрывают полный короткий матч, независимые типы кораблей, reconnect/
смену callsign, повтор смерти, старые события, запрет второй активной жизни,
выбор чужого корабля, 14→15 и отсутствие 16-го очка после завершения.
Есть тест 4×4×3: цель 15 недостижима без fallback, а не зависание навечно.
Snapshot сохраняется/восстанавливается без возврата потраченных слотов.

## Границы
Не менять gateway/Nasal/FGMS/launcher; не писать сетевой damage-server.
Резервирование спавна, rollback launch-failure и защита от поддельного урона
обозначаются в CONTRACT как следующие интеграционные задачи. До runtime-
подключения это не серверное принуждение и не античит.
